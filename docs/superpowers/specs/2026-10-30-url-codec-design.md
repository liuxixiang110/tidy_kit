# URL 编码/解码设计(百分号编解码,固定 UTF-8)

日期:2026-10-30
状态:实现完成后补记。按钮位置与"编码/解码"两个操作是需求方直接指定的,编解码语义分叉在会话中确认。

## 1. 背景与目标

调试接口时经常要把中文参数塞进 URL,或把一段 `%E4%B8%AD%E6%96%87` 还原成人话。
目标:一个标签内完成"粘进去 → 编码或解码 → 复制出来",不做多余的事。

## 2. 需求决议

- 入口:顶部按钮 `URL编码/解码`,位置在 `JSON对比` 之后(需求方指定)
- 操作:两个按钮 `编码` / `解码`,各自一次转换(需求方指定)
- 展现形态:上输入、下只读结果,与 HTML/XML 面板同构
- 标签名取短式 `URL n`:`URL编码/解码 1` 会把标签头撑得太宽
- 历史:不做(与 HTML/XML 一致);也不做模式开关

## 3. 架构

    src/main/java/com/tidy/kit/
    |- codec/  UrlCodec(encode / decode,纯静态,零依赖)
    |- ui/     UrlCodecPanel / JsonFormatterTabs

新包 `codec` 与 `format`、`parse` 同级:不 import Swing 与 com.intellij,可脱离 IDE 单测。
`UrlCodec` 无状态、不抛异常 —— 这是有意的(见 5.2),面板因此不需要 try/catch 与错误着色分支。

## 4. 编码语义

RFC 3986 百分号编码,固定 UTF-8:

- 保留未保留字符 `A-Za-z0-9-_.~`,其余字节一律转**大写** `%XX`
- 空格转 `%20`,**不是** `+`(`+` 代表空格是表单编码的私有约定,不属于 URL)
- 语义等同 JavaScript 的 `encodeURIComponent`,即"把一个值安全地塞进 URL",
  因此 `:` `/` `?` `&` `=` 都会被转义

实现是把整串按 UTF-8 取字节再逐字节判定,所以多字节字符与代理对天然安全;
输出长度上界约为输入的 3 倍。

## 5. 解码语义

### 5.1 只认 `%XX`,不动 `+`

不把 `+` 当空格。URL 里的加号常常是值本身(Base64 片段、数学表达式、搜索词),
按表单规则解会把 `a+b` 错解成 `a b`,而这不可逆 —— 用户看不出被改过。
因此 `a+b` 解出 `a+b`,`a%20b` 解出 `a b`。

### 5.2 宽松:非法序列原样保留,不报错

`100%`、`%zz`、`%2`(截断)这类不合法的百分号序列**原样保留**而非抛错。
理由是真实输入往往是混排文本(一句话里夹一段转义串),严格模式会让人什么都做不了。
同理,字面量非 ASCII 字符直接按 UTF-8 落进字节流,所以 `%E4%B8%AD文` 能正确解出 `中文`。

代价:字节流里若出现不完整的 UTF-8 序列(如 `%E4%B8` 少一字节),由 `new String(bytes, UTF_8)`
替换成 U+FFFD,不报错。这是"永不失败"取向下的预期行为。

### 5.3 实现要点

解码用"字面量先攒进 StringBuilder,遇到合法转义再整体 flush 成字节"的方式,
而不是逐字符 `getBytes()` —— 后者会把代理对从中间劈开。

## 6. UI 层

`UrlCodecPanel`:`JBSplitter` 上输入、下只读结果(各带 TitledBorder),控制行
`编码` `解码` | `清空` `复制结果` | 状态栏。

- 状态栏文案带字符数变化:`已编码,输入 12 字符 → 输出 36 字符`;
  结果与输入相同时追加 `(与输入相同,没找到需要转换的内容)` —— 这通常意味着用户粘错了内容
- 空输入不算错误,显示固定引导文案
- 状态着色与剪贴板复制走包私有 `ui/UiFeedback`,不在本面板重复实现
- 两个文本区都换行(不换行时拖选会膨胀到行尾,是本项目踩过的坑)

注册在 `JsonFormatterTabs`:新增 `urlCounter` 与 `addUrlTab(boolean focus)`,内部走公共
`addTab(panel, title, focus)`,自动挂上带 `×` 的标签头。

## 7. 测试

`UrlCodecTest` 11 项纯 JUnit:未保留字符白名单、保留字与空格转义(大写 `%XX`)、
中文与 emoji 代理对、控制字符、小写转义可解、混合内容往返、`+` 不动、
畸形序列原样保留、字面量非 ASCII 直穿、空与 null。

## 8. 已知取舍与后续候选

- **不支持 GBK 字符集**。老系统链接(`%D6%D0%CE%C4`)解出来是乱码。
  候选:加 UTF-8/GBK 下拉,或失败时提示"可能是 GBK"。
- **不做连续解码**。双重编码(`%25E4%25B8%25AD`)需要手动把结果复制回输入框。
  候选:加 `结果转输入` 按钮,或提供"解到不再变化为止"。
- 无历史池、无编辑器右键入口、无快捷键。
- 只实现 query 组件级编码;不做整条 URL 的分段智能编码(那需要区分 reserved 角色的语义)
